# 第 7 关（最终关）：MiniBoard —— 手搓一块能量产的温湿度采集小卡

**师傅开场白：**

前六关你把模电、数电、MCU、传感器、通信、固件的零件都备齐了。今天不学新零件，
今天**装整机**。师傅为什么把"做板子"留到最后？因为一块能量产的板子，考的不是
你会不会画某个电路，而是你能不能把**规格、功耗、成本、可测性、可靠性**这五把刀
同时架在自己设计的脖子上——任何一把没架住，量产出厂那天就是翻车那天。

这一关的项目叫 **MiniBoard**：USB-C 供电、SHT30 测温湿度、OLED 显示、带按键、
带报警、带看门狗、两层板 50×35mm、BOM 控制在 ¥25 以内。规格不多，但每一条都要
**算得出数字、跑得出程序、看得懂动画**。四个 .c 在 PC 上把整条链路的数字跑通，
一份 bring-up 剧本带你进实验室，一个动画把上电时序掰开揉碎给你看。

老规矩：**别信"看起来对"，信你亲手跑出来的数字。**

## 一、模块简介：为什么师傅最后才让你做板子

新人做板子有个通病：原理图抄模块、封装抄经验、布线凭手感，投板回来一上电——
要么 3.3V 只有 1.2V，要么 I2C 全 NACK，要么跑着跑着自己复位。然后开始"玄学修板"：
拍两下好了、换个 USB 线好了。这就是没做过整机的代价。

整机关教你的三件事，前面六关都教不了：

1. **全局约束互相打架**。客户说"静态电流 < 3mA"，你选的 OLED 全亮就 20mA；
   客户说"BOM < ¥25"，SHT30 加 OLED 加 MCU 就已经 ¥18；显示刷屏一堵 200ms，
   看门狗就咬你。做整机就是在约束的夹缝里找一条活路，而且每条活路都有代价。
2. **每个决定都要能落回数字**。LDO 还是 Buck？算给你看（phase1）。10k 上拉行不行？
   算上升时间给你看（phase4）。两层板够不够？算布线通道给你看。师傅可以替你拍板，
   但**理由必须是你自己的**。
3. **设计要为"修"留后路**。测试点、状态 LED、串口协议、BOOT0 处理——这些东西
   客户看不见，但首件上电那天，救你命的全是它们（phase5）。

所以本关不新增知识点，只做一件事：**把零件焊成一个能交付的东西**。

## 三、六个 phase 的顺序与验收标准

顺序是死的，别跳。每个 phase 结尾都有"跑完你应该看到什么数字"，
数字对不上就回头，别带病赶进度。

### Phase 1：电源树与功耗预算 —— `phase1_power_budget.c`

**做什么：** 上板之前先在纸上（代码里）把电源树和电流账算清楚。内建器件电流模型
（MCU 运行/睡眠、SHT30 平均与峰值、OLED 全亮/低亮/关屏、每个 LED、蜂鸣器、
LDO 静态电流），对三种工作模式（常亮 1Hz 采集 / 省电 10s 一次 / 报警）分别算轨电流、
LDO 热耗与温升（θJA）、假想 500mAh 锂电的续航、USB 500mA 裕量、上电冲击与
USB 输入 10µF 电容限制。

**验收标准（你应该看到的数字）：**

- 省电模式总电流 ≈ 1.68mA（3V3 侧）/ 1.72mA（折算到 USB 5V 侧），判定 **PASS（< 3mA）**；
- 程序故意演示的反例：OLED 常亮全亮 → 总电流 ≈ 30mA，**当场爆预算**，
  并打印出"是谁吃掉的"（OLED 排第一）——这就是"必须降亮度/定时关屏"的由来;
- 静态电流榜第一名是**电源 LED（1.2mA）**，不是 MCU——猜不到的回去重算;
- LDO 最坏温升 < 25°C（SOT-89，θJA≈250°C/W）；500mAh 锂电按省电模式续航 ≈ 298 小时
  （按 0.8 系数做工程折减后 ≈ 239 小时）；
- USB 输入电容 10µF ≤ 10µF 限制，浪涌检查 PASS。

### Phase 2：BOM 与规则检查 —— `phase2_bom_drc.c`

**做什么：** 用代码描述一张 ~40 个料号的完整 BOM（含封装、单价），按类别汇总、
算总价、估封装占用面积，然后跑一轮"软 DRC"规则检查：去耦是否齐、I2C 上拉阻值、
USB CC 下拉 5.1k、TVS 覆盖 USB 与 SWD、BOOT0 下拉、晶振负载电容与 CL 匹配、
蜂鸣器续流二极管、LDO 输入输出电容、PTC 保险丝……

**验收标准：**

- 总价打印出来 **< ¥25 且 PASS**（本次参考实现 ≈ ¥23.52，裕量只有 1.5 元，
  时刻提醒你这单是抠着做的；MCU+SHT30+OLED 三颗占 77%）；
- 检查结果 **恰好 3 个 FAIL**（SWD 无 TVS、蜂鸣器无续流二极管、晶振负载电容
  与 CL 不匹配）+ 3 个 WARN（I2C 上拉 10k 偏慢就是其中之一）。
  **FAIL 是师傅故意埋的**，你的作业是把它们找出来并说出每个 FAIL 的后果;
- 板面积占用估算 ≈ 610mm²，占 50×35=1750mm² 的 34.8% < 55% 红线，PASS。

### Phase 3：固件骨架 —— `phase3_firmware_core.c`

**做什么：** 在 PC 上用假时钟和外设影子寄存器搭分层固件，全程用嵌入式 C 的惯用
抽象：HAL 抽象层用一张 `struct HalOps` 函数指针表（GPIO、时钟、I2C、SPI、UART、
IWDG 各一列）注入模拟实现，驱动只认 `Hal` 句柄不认背后是真芯片还是 PC 上的
假硬件 → 驱动层（SHT30 含 CRC-8、SSD1306 最小指令集、按键消抖状态机、
LED 呼吸软件 PWM）→ 服务层（采样调度、滑动平均、阈值+滞回报警）→
应用层（INIT → SELFTEST → RUN → ALARM → SAFE 状态机 + IWDG 喂狗）。

**验收标准：**

- 跑 30s 仿真时间，逐 tick 打印温湿度/状态/喂狗情况，串口每秒一行 CSV；
- 上电 → 显示首帧耗时打印出来，**≤ 200ms**（模拟 SELFTEST 不刷屏）；
- t≈5s 注入 I2C CRC 错误：先重试 2 次，再**降级**（沿用上次有效值 + 打故障标志），
  程序不死、状态机不乱；
- t≈26s 注入主循环卡死 1.3s：IWDG（1s 超时）复位，重启后走 SELFTEST 回 RUN，
  全程打印"复位原因=看门狗"。

### Phase 4：通信与协议 —— `phase4_protocol_i2c.c`

**做什么：** I2C 时序模型（clock stretching、总线忙、NACK、从机拉住 SDA 的死锁）
+ 总线恢复（9 个 SCL 脉冲 + STOP）；上位机行协议（ASCII + CRC16-CCITT，命令
`READ_T` / `SET_THRESH` / `STATUS` / `CAL`）+ 抗噪解析器状态机；随机注入 5% 噪声
字节的回环测试；上拉电阻 × 总线电容的上升时间表。

**验收标准：**

- 死锁恢复演示：9 clock + STOP 之后总线恢复 ACK；
- 5% 噪声回环：解析器**不崩**，成功帧率、丢弃字节数、重同步次数三项统计打印，
  重同步后帧 CRC 全部正确；
- 上升时间表：2.2k/4.7k/10k × 50/150/400pF，tr = 0.8473·Rp·Cb（I2C 规范按
  30%→70% 定义 tr，0.8473 = ln(0.7/0.3)，不是 10%→90%）。结论要能讲：
  板上 ~150pF 时 10k 的 tr≈1271ns，连 100kHz 的 1000ns 限都超；4.7k≈598ns 是板载
  100kHz 的甜点位；要上 400kHz（限 300ns）得换 2.2k（≈280ns）。

### Phase 5：首件上电与量产剧本 —— `phase5_bringup.md`

**做什么：** 不是代码，是**能打印带进实验室的剧本**：物料核对、首件目视与关键点对地
阻值、**串灯泡限流上电**、分步上电电压表、烧录与 BOOT0 处理、逐模块点亮顺序、
规格回归测试表、"现象 → 定位方向"速查表、量产测试点与治具、HALT 老化。

**验收标准：** 你能拿着这张纸独立带一个新人完成首件上电，每一步都有"预期数字"，
不需要现场想。检查表里"串灯泡亮/不亮分别说明什么"你能脱口而出。

### Phase 6：整机仿真验收台 —— `phase6_bench.c`

**做什么：** 把 phase1~4 的模型串成"24 小时日历压缩版"：1 tick = 100ms，
跑 10000 ticks = 1000s（16.7 分钟固件时间），再等分映射到 24 格日历
（压缩比 86.4:1，不是真实 1 天），随机注入 I2C NACK、串口噪声、电源瞬时跌落 3.0V/5ms、按键连按、
温湿度阶跃、看门狗超时。固定随机种子，结果可复现。

**验收标准（期末成绩单，要求全 PASS）：**

- 10000 tick（1000s）不死机、无复位泄漏；
- 温湿度阶跃后报警触发延迟 ≤ 500ms（实测打印毫秒数）；
- 串口整帧通过率 ≥ 99%（按“发出 499 帧、完好收下 497 帧”算 = 99.60%；另有 1 帧被 CRC 拦下、1 帧中途重同步丢失，坏帧 0 渗入业务）；
- RAM/Flash 静态估算 < 20KB / 64KB 的 70%；
- 功耗逐 tick 累加，省电窗口平均 < 3mA；
- 末尾打印 24 格日历事件直方图 + 验收报告表格。

## 五、设计决策记录（ADR：选项 A/B + 决定 + 理由）

做整机不留决策记录，三个月后你就是自己的考古学家。这五条是本案的"五宗决定"。

### ADR-1：LDO 还是 Buck？

- **选项 A：LDO（ME6217C33，600mA，Iq 40µA，SOT-89，¥0.45）**
- **选项 B：1A Buck（同步整流，效率 ~90%，¥1.8 + 电感电容 ¥1.2）**
- **决定：A。**
- **理由：** 负载电流最大约 41mA，LDO 压差功耗 (5-3.3)V × 41mA ≈ 70mW，
  SOT-89 温升不到 20°C，热上完全安全。Buck 省的电在这块板子上是"芝麻"：
  省电模式（1.7mA 级）下 LDO 比 Buck 多耗约 11mA·h/天，常亮模式（16mA 级）
  才约 100mA·h/天——而客户要的电池续航发生在省电模式，瓶颈根本不在 5V 侧
  转换效率，而在负载本身。换来的是什么？Buck 开关纹波（几十 mV、几百 kHz）会直接糊到
  SHT30 的 I2C 和 NTC 的 ADC 采样上，你还得加磁珠、LC 滤波、走线隔离，
  成本 +¥3、面积 +80mm²、调试难度 +100。**电流小、噪声敏感器件多 → LDO；
  电流大（>150mA 量级）或者压差大（输入 12V 转 3.3V）才轮到 Buck。**

### ADR-2：SHT30 还是 DHT11？

- **选项 A：SHT30-DIS（I2C，±0.3°C / ±3%RH，带 CRC，¥7.5 批量价）**
- **选项 B：DHT11（单总线自定义时序，±2°C / ±5%RH，无 CRC，¥2.5）**
- **决定：A。**
- **理由：** 三个硬理由。①精度：客户的报警阈值是 45°C，DHT11 ±2°C 意味着
  43~47°C 都可能触发，阈值形同虚设；②可靠性：SHT30 每帧带 CRC-8，通信错误
  可检测（phase3/4 里演示的就是它），DHT11 的单总线时序靠延时循环，中断一抖
  就废，还没法校验；③集成度：SHT30 两线上总线，DHT11 还要 4.7k 上拉 + 精确
  us 级时序。**"便宜 ¥5"买不来"可验证"。** DHT11 唯一赢面是钱，本案 BOM 装得下。

### ADR-3：两层板够不够？

- **选项 A：2 层（50×35mm，打样 ¥30，贴片 ¥0.06/焊点）**
- **选项 B：4 层（同尺寸，打样贵 3~4 倍，工程量 +完整叠层/阻抗思维）**
- **决定：A。**
- **理由：** 本案最快的信号是 8MHz 的 HSE 时钟/晶振走线和 10MHz 级 SPI（SSD1306 典型
  SPI 时钟 2.5~10MHz），I2C 100kHz，UART 115200——**没有一个需要受控阻抗的**。
  顶层走信号、底层整块地，50×35mm 上 40 个料号布线通道够用（phase2 面积估算
  约 34.8% 占用，低于 55% 红线）。4 层板当然也能给电源/地平面、降低回流阻抗、
  改善 EMI，但本案两层板 + 底层整块地已经够用；把地硬拆成"模拟地/数字地"不是收益，
  反而是常见错误。整块单一地平面 + 按回流路径分区布局才是更对的 answer。
  **板层数是省出来的，不是买心安买出来的。**

### ADR-4：HSE 为什么选 8MHz？

- **选项 A：8MHz 晶振（×9 → 72MHz，PLL 常规档）**
- **选项 B：16MHz 晶振（×4.5，F103 的 PLL 倍频系数没有 4.5 这一档）**
- **决定：A。**
- **理由：** STM32F103 的 PLL 倍频档是 ×2 ~ ×16，外加 ×6.5/×7.5/×8.5/×9.5
  几个半档，**没有 ×4.5**；8MHz × 9 = 72MHz 是 datasheet 的标准推荐路径，
  SYSCLK 精确 72MHz。16MHz 要凑 72MHz 只能 ×4 = 64MHz，或者硬超到 72MHz 以上，
  USB 的 48MHz 分频和 UART 波特率误差都会变难看。另外 8MHz 是量产备货最容易的
  频点，负载电容配 12pF 晶振时每只电容按 2×(CL−Cstray) = 2×(12−4) = 16pF 选
  （本案 27pF 是**故意埋的错**，phase2 会 FAIL 给你看；16pF 才是正确档）。

### ADR-5：IWDG 还是 WWDG？

- **选项 A：IWDG（独立看门狗，LSI ~40kHz 独立时钟，超时 ~1s 可配）**
- **选项 B：WWDG（窗口看门狗，PCLK 分频，有"喂狗窗口下限"，可提前中断预警）**
- **决定：A 为主，不用 WWDG。**
- **理由：** 客户要的是"24 小时不死机"，即**程序跑飞了必须自己爬起来**，
  IWDG 用独立 LSI，主时钟停了、PLL 飞了它照样咬，这是"保命"。WWDG 的价值在
  "喂狗太早也复位"，能抓"逻辑跑太快/提前喂狗"这类时序病，但它挂在 PCLK 上，
  时钟一飞它就先死了——保命能力反而弱。本案的"卡死检测"用 IWDG 足够；
  WWDG 留作课后题（家庭作业 4）：**两者同开，喂狗点怎么排？**

## 六、学习建议与常见坑（血泪清单，每条都值一块板的钱）

师傅先说用法：这 12 条不是背的，是让你在 phase6 仿真、phase5 实验室里
**一条条对上号**的。对上一条，这条坑就是你的了。

1. **USB-C 不接 CC 下拉电阻 → 对方根本不给你电。** USB-C  Source 靠 CC 上
   Rp 检测对端 Rd（5.1k 下拉）才闭合 VBUS。只焊了 C-C 线没焊 5.1k，你的板子
   接上去就是 0V，还以为是 LDO 坏了。两路 CC 各焊一颗 5.1k。
2. **LDO 输出电容 ESR 太低导致振荡。** 老架构 LDO（某些固定 3.3V 的 SOT-89 廉价料）
   datasheet 明写"需要 ESR 0.1~2Ω 的电容"，你手一抖焊了 MLCC（ESR 几毫欧），
   输出相位裕度没了，3.3V 变成几百 kHz 的小摆幅"抖振"，ADC 读数跟着抖。
   选型时**先看输出电容 ESR 要求**，或换明确"支持全 MLCC"的 LDO（本案 ME6217）。
3. **SHT30 的 I2C 上拉在 3.3V 下取 10k 偏慢。** 上升时间 tr=0.8473·Rp·Cb，
   10k × 150pF ≈ 1271ns，连 100kHz 的 1000ns 限都超标，板上再多两片器件、线一长到
   300pF+ 更是直接通信报错，而且**时好时坏**（温度高更慢）。默认 4.7k（≈598ns），
   要跑 400kHz 或长线用 2.2k。
4. **BOOT0 与按键复用 → 想进 bootloader 进不去 / 想跑程序跑不了。** 复用的
   代价：上电瞬间按住这个键就是 bootloader 模式。固件升级流程必须文档化：
   "按住 KEY2 插 USB"。BOOT0 必须外加 10k 下拉，否则悬空的 BOOT0 被 SWD 排针
   上窜进来的干扰一拉高，板子"随机"不进 APP，量产现场能把你查疯。
5. **SWD 引脚被外部上/下拉或短路干扰。** SWDIO 内部上拉、SWCLK 内部下拉，
   外部再挂强下拉会让调试器连不上；排针上插着一根短路的杜邦线，也可能把
   MCU 拽进异常状态。**上电做 BOOT 决策的是 BOOT0（以及 F103 的 BOOT1/PB2），
   不是 SWDIO/SWCLK**，别把两件事混为一谈。SWD 走线不加上/下拉，排针位置
   别靠近连接器防手碰短路。
6. **蜂鸣器三极管没并续流二极管 → MCU 时不时复位。** 三极管开关感性负载
   （尤其是带内部线圈的有源蜂鸣器/电磁式），关断瞬间 -L·di/dt 在集电极打出
   上百伏尖峰，通过电源轨把 3.3V 打出毛刺，MCU 走 BOR（欠压复位）还查不出原因。
   1N4148 反并联在蜂鸣器两端，BOM 里 ¥0.02，救一整批货。
7. **ADC 参考与电源噪声耦合。** NTC 分压和 VDDA 都取自 3.3V 时，缓慢的轨压
   变化会按比例同时作用在分压比和参考上，**一阶相消**——这是比率测量的好处。
   真正要防的是"分压点的局部瞬态"与 VDDA 不同步：OLED 刷屏瞬间抽电流，
   走线阻抗和磁珠让两处电压短时不一致，读数就会跳零点几度。对策：NTC
   分压加 100nF 就近储能 + 门控供电 + 采样时错开刷屏时刻 + 软件多次过采样。
8. **显示刷屏阻塞导致看门狗复位。** SSD1306 全屏 1KB 数据，软件 SPI 慢一点
   就是 100+ms；你偏偏把整屏刷新写在主循环一个函数里，中间没喂狗，IWDG 1s
   超时、三次重绘就复位一次。刷屏拆块（每 1/8 屏喂一次狗）或 DMA+中断。
   phase3 的喂狗点安排就是练这个的。
9. **量产忘了在固件里留测试点。** 硬件留了 TP，固件没留"产测模式"：治具短接
   TP1+TP2 上电应进自检并闪烁全部 LED。没这个，产线只能靠人眼看灯，误判率
   感人。固件的自检模式是设计的一部分，不是可选装饰。
10. **USB / 热插拔的 ESD 没做 TVS。** 用户冬天摸板子"啪"一下，USB 数据口
    过 IEC 61000-4-2 ±4kV 接触放电，没有 USBLC6 这类阵列 TVS，MCU 的 IO
    第一个殉职。同理 SWD 排针是外露金属，也要 TVS——phase2 故意没放，
    检查清单里 FAIL 的就是它。
11. **首次上电直接怼电源，短路了烧一片。** 首件永远**串灯泡上电**
    （phase5 全套剧本；5V 板用 12V 5W 灯泡，220V 100W 灯泡在 5V 下几乎不亮）。
    灯猛亮=有短路，基本不亮=正常待机，暗红微亮且发热=异常漏电。省下的
    不是一块板，是你的工期。
12. **电源轨"有电压没电流"骗过万用表。** 反馈电阻虚焊时 LDO 输出可能"量起来
    3.3V"，一接负载立刻塌。关键点不仅要量电压，还要**加负载复测**与
    **对地阻值**（phase5 表格里给了预期范围）。

**学习建议（师傅的口诀）：** 先跑 phase1 把电流账背下来，再跑 phase2 把三个
FAIL 找出来写进笔记；phase3/4 改参数玩（把上拉改 1k 看 tr 变多少、把看门狗
改 100ms 看复位几次）；phase5 打印出来贴在桌上；最后 phase6 当期末考试，
成绩单全 PASS 才准合上这一关。

## 七、家庭作业

1. **改 phase1：** 把电源 LED 从 1.2mA 改成呼吸模式（平均 0.3mA），重新算省电
   模式总电流和续航；再假设客户加需求"OLED 常显"，重新算——预算还够吗？
   写出你要砍谁的电流。
2. **修 phase2 的三个 FAIL：** 给 SWD 加 TVS 阵列、给蜂鸣器加 1N4148、把晶振
   负载电容从 27pF 改对（晶振 CL=12pF，杂散 4pF，按 CL=(C1/2)+Cstray 反算）。
   改完总价涨了多少？还 < ¥25 吗？
3. **改 phase3：** 把报警阈值 45°C 改成 40°C、滞回从 2°C 改成 1°C，观察
   ALARM/RUN 回跳次数变化；说出滞回太小会发生什么（提示：报警抖振）。
4. **思考题（IWDG + WWDG 同开）：** 主循环每 100ms 跑一圈，IWDG 超时 1s，
   WWDG 窗口下限 200ms。喂狗点放哪两个位置才不被 WWDG 咬又保得住 IWDG？
   画时序图。
5. **手工活（最有价值）：** 拿 50×35mm 方格纸（或任意免费 EDA）把 MiniBoard
   摆一遍：USB-C、LDO、MCU、SHT30、FPC 座、蜂鸣器、三个 LED、两个按键、
   4 个测试点。**要求把 4 个测试点放在：VBUS、3.3V、SWDIO、GND**，
   并把 SHT30 放在远离 LDO 和蜂鸣器的角落。拍照存进你的作品集——这就是你的
   "毕业证设计"。
