硬件工程师 · 修炼路线图

从点灯到交钥匙 —— 七关修成硬件工程师

这不是一本教材，是一个老师傅带徒弟的过程。每一关三件套：主课本（把道理讲透）、 能跑的 C 程序（把数字算给你看，不是"显然可得"）、可交互的动画（把看不见的电流、 波形、回流路径变成能拖能拽的东西）。学完第七关，你手里会有一块自己画、自己焊、自己调通、 自己写完固件并交出一份验收报告的板子。

示例语言：C17（gcc 单文件，无需 IDE） 动画：离线单文件 HTML，双击即开 前置：欧姆定律 + 基础 C 产出：一块 MiniBoard + 一份验收报告

00开始前的三件事

别急着看第 1 关，先把工具和环境弄利索，否则会卡在"跑不起来"上而不是"看不懂"上。

① 装编译器（只要 gcc，不要 IDE）

  • Windows 装 MSYS2，然后 pacman -S mingw-w64-ucrt-x86_64-gcc；Linux/macOS 自带或 apt install build-essential / xcode-select --install。
  • 验证：gcc --version，C17 需要 gcc ≥ 8；本项目在 GCC 16.2 上验证通过。全套示例只用标准库，不联网、不装包。

② 运行任何示例前先敲这一句（Windows 专用，忘了就会骂娘）

# 把控制台切到 UTF-8，否则中文全是乱码方块
chcp 65001

# 然后编译 + 运行，每个文件都是独立的，一行搞定
gcc -std=c17 -O2 -Wall -Wextra 01_node_solver.c -o demo.exe
./demo.exe

③ 动画页面怎么打开

  • 所有 *.html 都是纯离线单文件：没有 CDN、没有外部字体脚本，断网也能跑。双击就行。
  • 滑杆拖一拖再回课本，比盯着公式猜"为什么"快得多。动画不是玩具，是让你把看不见的东西（回流电流、亚稳态窗口、去耦阻抗）看见。

›修炼主线

顺序是有讲究的：算得准 → 看得懂器件 → 数字跑得稳 → 芯片用起来 → 板子画得出 → 出问题查得动 → 全部合成一个真项目。

会算（KCL/KVL）→ 会看器件（二极管/运放/电源）→ 数字系统跑得稳（时序/亚稳态）→ 芯片用起来（寄存器/总线/中断）→ 板子画得出（阻抗/回流/EMC）→ 坏了查得动（仪器/排障）→ 交钥匙（MiniBoard）

※老师傅的六条叮嘱

  • 先算再焊。算不出来就不要通电。"上电看看"不是方法，是赌博，赌注是你的板子和万用表。
  • 所有"显然"都要验。软件里可以相信类型系统，硬件里你不能相信"这个电容应该就是 100nF"——它有 20% 容差、有 DC 偏压衰减、有 19MHz 自谐振。
  • 每个示例都自己跑一遍。课本里写的数字（0.95A、89.29MHz、−4.8%）你必须能亲手复现，复现不了就说明你没懂，或者你的单位换错了——后者占九成。
  • 改参数是学习的一部分。每个 .c 顶部都留了参数区；把 4.7k 改成 10k、把时钟从 72MHz 改成 8MHz，看数字怎么崩，比读三遍文字有效。
  • 动画不是装饰。看不懂回流路径时先玩 return_path_animator.html；被亚稳态绕晕时先拖 setup_hold_animator.html 的滑杆。先建立直觉，再回去推公式。
  • 过不去就回头看。第 5 关画不出阻抗控制，多半是第 1 关的等效电路没扎实；第 4 关调不通 I2C，多半是第 1 关的 RC 上升时间没算过。硬件没有跳级这回事。
