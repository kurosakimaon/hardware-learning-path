## 一、模块简介：为什么先学寄存器点灯，再上 HAL

网上教程九成从 HAL 开始：`HAL_GPIO_WritePin(LED, PIN, SET)`，一行点亮，三分钟发朋友圈。快是快，可三个月后你遇到下面这些场景就抓瞎了：

- 示波器挂着 I2C，SCL 被从机拉死，HAL 的 `HAL_I2C_Master_Transmit` 只会超时返回 ERROR——为什么超时？恢复动作是什么？HAL 不管，你得懂总线。
- 串口偶尔丢字节，波特率明明一样。你不懂 BRR 怎么来的、采样点在哪，就只能玄学换线。
- 产品跑一天死一次。看门狗"配了"，等于没配——无条件喂狗的看门狗是给自己壮胆的。
- HAL 升级后同样的代码时序变了，你连"变在哪"都说不出口。

寄存器不是复古，是**你和芯片之间唯一的、不会骗人的接口**。HAL、LL、CubeMX 生成的代码，全是寄存器操作的包装纸。本关用软件模型把 GPIO / USART / I2C / NVIC 的寄存器行为原样搬到你电脑上——**没有硬件也能把这一关练完**，每个 .c 都能编译运行，打印出的寄存器快照和真芯片逐位一致。

学完这关再回头看 HAL，你读到的不再是函数名，而是它背后动了哪几个位。

## 二、硬件工程师为什么必须懂一点固件

你不是要去当固件工程师，但以下时刻救你的都是固件内功：

1. **板级联调**。新板回来，第一口气是固件给的。SWD 连不上，到底是 SWDIO 被复用成了 JTAG 的其他脚、boot0 焊错、还是电源轨没起来——分不清这些，你就在换芯片碰运气。
2. **外设之间的边界问题**。I2C 上拉电阻是硬件选的，上升时间却是固件时序要求的；SPI 模式 CPOL/CPHA 写在固件里，示波器上量的是硬件波形。边界两头你都得会看。
3. **看懂固件同事的现场**。他说"中断优先级不够"，你要知道那是 NVIC 抢占分组的事；他说"堆栈溢出"，你要能问出中断嵌套深度和局部数组多大。
4. **失效分析**。芯片烧了、锁了、参数漂了，Readout Protection、Option Bytes、总线恢复——全是软硬交界面上的事。

一句话：**懂固件的硬件工程师，联调时不用排队等人；懂硬件的固件工程师，代码不会让板子冒烟。**

## 三、学习目标（每条都可自测）

学完本关，你应该能：

1. **口述一个 STM32 GPIO 引脚从上电到点亮 LED 经过的每一步**：复位后引脚是输入态（MODER=00；F103 用的 CRL/CRH 复位也是浮空输入）→ 配输出 → 配速度 → ODR 写值 → 电流从哪个管脚出去、灌进哪个元件。并能解释为什么 L0/L4 复位直接是模拟态（MODER=11），以及未使用引脚为什么建议配成模拟输入。
2. **只给芯片手册，配出 115200-8N1 的 BRR 值并解释误差**：72MHz PCLK 下 USARTDIV=39.0625，BRR=0x271，误差 0.00%；8MHz 下 BRR=0x045，实际 115942bps，偏差 +0.64%——并说清 ±2% 误差预算是怎么从 8N1 采样几何里推出来的。
3. **给一条具体 I2C 总线算出上拉电阻区间**：Rmin=Vdd/Iol（3.3V/3mA≈1.1kΩ），Rmax=tr/(0.847·Cb)（1000ns/150pF≈7.9kΩ），并解释为什么区间为空时唯一出路是降容性或降速率，而不是"电阻再小点"。
4. **徒手算最坏中断响应延迟**：临界区剩余时间 + 上级 ISR 尾巴 + 入栈时间，能算出本关模型里 TIM 的 40µs 最坏延迟从哪来；也能说清"高优先级 ISR 忙等 5ms"为什么会把低优先级中断饿死、把看门狗喂断。
5. **看懂 SWD 连不上时的三种典型原因**并给出对应救法：复位引脚被复用/没给复位、SWD 引脚被固件配成其他功能（用 BOOT0 进 System Memory 擦掉固件）、供电或时钟没起来（先量 1.8/3.3V 和 HSE 波形再谈连接）。
6. **解释看门狗超时怎么算**：IWDG 超时=预分频×(重装值+1)÷40kHz，LSI 实际 30~60kHz，标称 400ms 的窗口实际是 267~533ms——并能说出"有条件喂狗"的判据怎么写。
7. **在沙盒里复现并解释 ODR 读改写事故**：`ODR = 1<<3` 为什么会抹掉别的引脚？和 `BSRR = 1<<3` 差在哪？配合 register_playground.html 里"错误示范"按钮亲眼验证一次。

## 五、主线知识：四块寄存器，四堂课

### 5.1 GPIO：所有外设的入门课

STM32 每个 GPIO 引脚由 7 个寄存器位段共同决定：MODER（模式，2 位/脚）、OTYPER（推挽/开漏）、OSPEEDR（驱动速度）、PUPDR（上下拉）、IDR（只读输入）、ODR（输出锁存）、BSRR（原子置位/复位）。

三个必须刻进肌肉记忆的结论：

1. **MODER 编码先背熟**：00=输入、01=输出、10=复用、11=模拟。复位后引脚是什么态分系列：F4/G/H 多数脚复位为 00 输入，L0/L4 复位直接是 11 模拟，F103 根本没有 MODER（用 CRL/CRH，复位为浮空输入）。**未使用的引脚建议主动配成模拟输入（11）**：输入缓冲不工作，不耦合数字噪声、不漏电。固件第一件事就是"把要用的引脚从复位态里配出来"。
2. **BSRR 的存在就是为了消灭读改写**。`ODR |= (1<<3)` 是三步：读 ODR、或上掩码、写回。若在读和写之间中断改了别的引脚位，写回就把中断的成果抹掉了。`01_gpio_registers.c` 里演示得明明白白：主循环和中断赛跑，ODR 路径输出 0x28（丢了中断刚点亮的 PA7），BSRR 路径 0xA8（PA3/PA5/PA7 全保住）。**带中断的系统里，改 GPIO 输出只有 BSRR 一种正确姿势。**
3. **速度档不是"越快越好"**。OSPEEDR 控制的是内部驱动管的开关斜率，档位越高边沿越陡、振铃和辐射越大。点 LED 用低速档；只有真上 10MHz 以上信号（SPI/QSPI）才开高速档。拿高速档直推 LED 不会更快，只会更吵。

顺带一个硬件向的坑：**GPIO 直推 LED 要算限流电阻**。F103 单脚的 VOL/VOH 是在 8mA 条件下考核的（绝对最大 25mA 是"不许超过"不是"可以长期用"，整个端口合计还有 150mA 上限），红色 LED 压降约 1.8V，3.3V 供电串 330Ω~1kΩ 正合适。见过太多板子拿 GPIO 直接怼 LED 再串 100Ω，单脚长期跑 15~20mA，三年后那个脚漏电。

#### GPIO 寄存器速查（对着 register_playground.html 逐位看）

以 STM32F4 的 GPIOA 为例，基地址 `0x4002 0000`（F103 是 `0x4001 0800`，且没有 MODER，用 CRL/CRH）：

| 偏移 | 寄存器 | 位宽布局 | 复位值 | 一句话职责 |
|---|---|---|---|---|
| 0x00 | MODER | 2 位/引脚 | 全 0（输入；GPIOA 实为 0xA8000000） | 引脚是谁：输入/输出/复用/模拟 |
| 0x04 | OTYPER | 1 位/引脚 | 0（推挽） | 输出是推挽还是开漏 |
| 0x08 | OSPEEDR | 2 位/引脚 | 0（低速） | 输出边沿有多陡 |
| 0x0C | PUPDR | 2 位/引脚 | 0（浮空） | 内部上拉还是下拉还是不拉 |
| 0x10 | IDR | 1 位/引脚 | — | 引脚上的**真实电平**（只读） |
| 0x14 | ODR | 1 位/引脚 | 0 | 输出**锁存器**的值（不是引脚值！） |
| 0x18 | BSRR | 低 16 置位 / 高 16 复位 | — | 原子写：写 1 生效，写 0 无动作 |

注意两个容易读错的点：

- **ODR 读出来是锁存值不是引脚电平**。引脚被外部强拉到 0，推挽输出的 ODR 读出来照样是 1。想知道引脚真实电平，读 IDR。沙盒里 IDR 一栏专门按"电路模型"推断，跟 ODR 经常不一致，就是这个原因。
- **BSRR 写 0 的位是不动的**，这是它原子的来源：置位区和复位区一次写死，硬件保证同一拍生效，中断插不进缝。

师傅答疑（沙盒里被问过最多的三个）：

> 问：把 PA5 配成复用推挽，等效电路里的两个 MOS 管怎么不亮了？
> 答：复用模式下两个管子的栅极不再接 ODR，改接片上外设（TIM 的 CH 信号、USART 的 TX 等）。沙盒里显示 `A`（外设驱动）就是这个意思——寄存器你配的是"把引脚交给外设"，电平归外设说了算。

> 问：输入模式下 IDR 一直是 `X`？
> 答：因为你把它设成浮空输入又没给外部信号。真实电路里浮空引脚电平不确定，数字上读 0 还是 1 全凭天意——所以未用引脚要么配模拟态，要么内部上下拉，**不许留浮空**。

> 问：开漏输出拉低时，上拉电阻接不接都能把线拉低，为什么还说必须接？
> 答：拉低靠的是下管，确实不靠上拉；但开漏没有能力把线拉高，释放后必须有人把线抬回 VDD。不接上拉，线就停在浮空/低电平，主机根本发不出 STOP，协议上不叫通信。单总线可以靠内部弱上拉凑合（通常几十 kΩ，只适合短线低速），标准 I2C 必须外部上拉，而且要认真算（见 5.3）。

#### 主循环消抖：100 tick 里的 20ms 哲学

机械按键闭合瞬间，触点是弹跳的——示波器上能看到几毫秒内十几次的高低抖动。硬件治法是 RC+施密特触发器或专用芯片，固件治法是**状态机 + 时间窗**，01 的模型：

```text
每 1ms tick 采一次 IDR：
  稳定态  ──采到相反电平──▶  确认态（开始计数）
  确认态  ──连续 20 拍电平一致──▶  翻转稳定态，报告"按下"
  确认态  ──电平又变回去──▶    回稳定态（判定为抖动，作废）
```

关键不是"延时 20ms 再读"这种土办法（把 CPU 按在原地睡觉），而是**状态机不阻塞**：主循环照跑别的任务，1ms 来看一眼。20ms 是经验窗——大多数触点弹跳 <10ms，你的采样窗至少要 2 倍于弹跳时间。硬件工程师要能反问：为什么固件能软件消抖，板级还常放 100nF？答：省固件 CPU 预算、给外部中断（EXTI）用的信号必须先硬件整形，否则一次按键进十几次中断——又是中断风暴。

### 5.2 UART：没有时钟线的信任游戏

UART 全凭两边各自数格子。三个数：

- **BRR 怎么来**：`USARTDIV = fck / (16 × Baud)`，整数部分进 BRR[15:4]，小数部分 ×16 四舍五入进 BRR[3:0]。`02_uart_timing.c` 的表：72MHz→115200 得 BRR=0x271，误差 0.00%；8MHz→115200 得 BRR=0x045，实际 115942bps，偏差 +0.64%；8MHz→921600 误差 −3.55%，直接标红——**这个组合根本不该出现在设计里**。
- **±2% 预算怎么推**：8N1 一帧 10 位，接收端在起始位下降沿对齐后一路数到停止位采样点（第 10 个采样点，距起始沿 9.5 个位宽）。每位容错半格，摊下来总预算约 ±5.26%；工程上要求单边（TX 或 RX）误差 ≤ ±2%，两边最坏合计 ±4%，相对理论极限留约 1.26% 余量。晶振、BRR 取整、温漂都算在这 2% 里。**误差是链路上所有环节的总和**，不是你一个 BRR 的事。
- **帧模拟的教训**：慢 6% 时，D7 的采样点（8.5×1.06≈9.01）已经跨进停止位，0x55 被读成 0xD5；而停止位采样点落在空闲高电平上仍读到 1，硬件不报帧错误——这就是最阴的**静默错码**。快 6% 反而好查：停止位采样点（9.5×0.94≈8.93）落进 D7，直接报 FE。8N1 没有校验位，慢漂移造成的单比特翻转没人拦；开奇偶校验至少能把这类错误暴露出来，工业链路别嫌麻烦。

环形缓冲区部分记住一句话：**RXNE 中断里只做一件事——搬字节进环形缓冲**。任何解析、打印、组帧都放主循环。缓冲满了怎么办？要么丢最旧、要么置溢出标志，但**绝不能在中断里等着主循环消费**——那就是拿中断当睡眠用。

#### BRR 手算示范（跟着走一遍，考试就这个难度）

目标：72MHz PCLK2，115200bps，8N1。

```text
第一步  USARTDIV = 72 000 000 / (16 × 115 200) = 39.0625
第二步  整数部分 mant = 39 = 0x27
第三步  小数部分 frac = round(0.0625 × 16) = round(1.0) = 1 = 0x1
第四步  BRR = (mant << 4) | frac = 0x271
第五步  回代验误差：USARTDIV' = 39 + 1/16 = 39.0625
        实际波特率 = 72 000 000 / (16 × 39.0625) = 115 200 → 误差 0.00%
```

再看反面教材：8MHz 跑 921600。USARTDIV = 8e6/(16×921600) = 0.5425，mant=0、frac=round(8.68)=9，USARTDIV'=0.5625，实际波特率 888 889，偏差 **−3.55%**——超预算，这条链路在设计阶段就该被毙掉，别指望"先焊上试试"。

#### 采样几何：±5.26% 是怎么来的

```text
发送端位周期 = 1.000 T，接收端位周期 = r·T（r=1+ε）
接收端第 k 格的采样时刻（以发送端时间轴计）：t_k = (k + 0.5)·r
k=0 是起始位，k=9 是停止位：停止位采样点 t_9 = 9.5·r
它必须落在发送端停止位窗口 [9, 10] 内：
       9 ≤ 9.5·r ≤ 10   →   0.9474 ≤ r ≤ 1.0526   →   |ε| ≤ 5.26%
```

这是**两端误差合起来**的理想极限，且最后一位恰好压在边缘。工程上单边按 ±2% 封顶（晶振 ±20ppm 忽略不计、BRR 取整与温漂各占一点），两边最坏合计 ±4%，相对 5.26% 留约 1.26% 余量。uart_frame_animator.html 里两边反向各推到 ±2.7%，快的一侧 r≈0.947、慢的一侧 r≈1.056，正好顶到停止位窗口的两条边，和上面的公式严丝合缝。

### 5.3 I2C：三根线上全是人情世故

I2C 只有两根线（SCL/SDA），全是开漏+上拉，所以：

- **线与是物理属性**：任何一个设备拉低，线上就是低。主机读回 SCL 发现自己放不低——那是从机在 stretching，它还没准备好，你在硬件层面就得等。
- **上拉电阻是区间不是定值**：小头 Rmin=Vdd/Iol，保证拉得低（3.3V/3mA → 1.1kΩ）；大头 Rmax=tr/(0.847·Cb)（tr 按 I2C 规范的 30%~70% 量），保证升得起（1000ns/150pF → 7.9kΩ）。算出来区间为空（比如 300ns/1000pF 的极端组合，Rmax=354Ω < Rmin）,唯一出路是**降总线容性（短线、少器件）或降速率**，硬压电阻只会把驱动管烧在饱和里。
- **死锁与 9 脉冲恢复**：从机在发送数据中途被复位，它以为还欠半个字节，把 SDA 死死拉低；主机看到 SDA 低永远发不出 START。救法：主机把 SCL 当通用输出**打 9 个脉冲**，从机数满 9 位发现收到的是垃圾，释放 SDA，再来个 STOP，总线复活。`03_i2c_bus.c` 完整演示了死锁形成和 9 脉冲恢复全过程——这段代码逻辑值得抄进你所有 I2C 驱动的初始化里。

#### 上拉电阻实算四连（03 程序输出，手算一遍再对答案）

| 场景 | Rmin = Vdd/3mA | Rmax = tr/(0.847·Cb) | 结论 |
|---|---|---|---|
| 3.3V / tr≤1000ns / Cb=150pF | 1.1kΩ | 7.87kΩ | 选 2.2k~4.7k 舒服 |
| 3.3V / 1000ns / 100pF | 1.1kΩ | 11.8kΩ | 容性小，空间更大 |
| 3.3V / 300ns / 1000pF（长排线挂满器件） | 1.1kΩ | **354Ω** | **区间为空**：降容性或降速率，没有第三条路 |
| 5V / 1000ns / 200pF | 1.67kΩ | 5.9kΩ | 5V 抬高 Rmin，注意别选到区间外 |

0.847 这个数的来历：RC 充电 V(t)=Vdd·(1−e^(−t/RC))。充到 30% 用时 t₃₀=−RC·ln(0.7)，充到 70% 用时 t₇₀=−RC·ln(0.3)，相减得 tr = RC·ln(7/3) = **0.847·RC**。别背过程，背结论：**tr 和 Cb 定死了 R 的上限，灌电流定死下限**。

师傅答疑：

> 问：总线 100kHz 用得好好的，换到 400kHz 偶发地址 NACK，为什么？
> 答：400kHz 规范 tr≤300ns。你的上拉和容性按 100kHz（tr≤1000ns）选的，升速后上升沿不达标，第 7 位数据爬不到阈值，从机采样出错。回表重算 Rmax——通常答案不是换电阻，是总线本来就超长超容，400k 是选配不是标配。

> 问：为什么我读 SDA 读到的和示波器不一样？
> 答：多半是你读寄存器时机不对（还在 SCL 低电平期间），或者总线上有第二个主机/stretching 的从机在拉。I2C 的"读回"永远以引脚真实电平为准——这也是为什么 HAL 的 I2C 反复检查 SB/ADDR 标志而不是写完就当成功。

### 5.4 调度与中断：软件世界的"总线仲裁"

裸机调度的本质是**有限资源（CPU 时间）上的抢占仲裁**，规则全在 NVIC：

- **优先级分组决定话语权怎么切**。分组 2（2 位抢占 × 2 位子优先级）下，只有抢占值严格更小才能打断正在跑的 ISR；子优先级只决定同拍挂起时谁先上，没有打断权。把这两层混为一谈的人，配置表写出来自己都不敢信。
- **响应延迟是可以算的**：最坏延迟 = 当前临界区剩余 + 正在跑的上级 ISR 尾巴 + 入栈时间。本关模型里 TIM 的最坏延迟 40µs 就是这么来的（临界区 40µs 卡在前面）。**不知道最坏延迟的系统，不配叫实时系统。**
- **ISR 里忙等 = 犯罪**。演示二让 TIM ISR 忙等 5ms：周期才 1ms，返回当拍下一发已经挂起、无缝二次进入，TIM 连占 99000µs，主循环一步跑不到，喂狗 0 次，IWDG 在 100ms 处准时复位。修正版 ISR 只干 2µs（置个标志），重活挪给主循环延迟队列，跑满 100ms 不复位。**ISR 的字数（指令数）要像省电一样省。**
- **裸机优先级反转**：高优先级任务 REQ 等低优先级 LOW 干活，中优先级 MED 把 LOW 切了，REQ 跟着陪葬——完成延迟从 601µs 恶化到 1401µs。裸机治法朴素但有效：**给实际干活的人提高优先级**（优先级天花板的平民版）。
- **看门狗**：超时 = 预分频 × (重装值 + 1) ÷ 40kHz（LSI）。标称 400ms，LSI 实际 30~60kHz，真实窗口 267~533ms——设计时要按最坏算。喂狗的唯一正确姿势是**有条件喂**：主循环把每个关键任务置心跳位，全部心跳齐了才喂。演示二里"表里那几次喂狗都是风暴前跑完的"，风暴一来立刻断喂，狗才起作用。

#### NVIC 优先级速查（分组 2，本关模型默认）

```text
raw 优先级（4 位）→ 高 2 位 = 抢占级，低 2 位 = 子优先级
  0b0000 = 抢占 0 子 0（最高）      0b1111 = 抢占 3 子 3（最低）
抢占规则：候选抢占值 < 正在跑 ISR 的抢占值 → 打断（当拍入栈嵌套）
子优先级：只排同拍挂起队的座次，永远不能打断任何人
PRIMASK：主循环临界区置 1，屏蔽一切中断——最坏延迟的头号贡献者
```

04 演示一的三个中断源并非全同级：TIM raw=0b0010 是抢占 0，UART/ADC raw=0b1100/0b1101 是抢占 3。抢占次数为 0 是因为 TIM 的事件没有落在 UART/ADC 的 ISR 窗口里，而不是"同级不能抢"。想做打断实验，把 ADC 的 raw 改成 0b0100（抢占 1），它就能把 UART（抢占 3）拦腰砍断；但 TIM 仍是抢占 0，ADC 抢不了 TIM，TIM 的最坏延迟不变。自己改了自己算，算对了才算懂。

#### IWDG 超时计算表（04 演示五原样输出）

| 预分频 | 重装值 | 标称超时 | 备注 |
|---|---|---|---|
| 4 | 0 | 0.1 ms | 重装值 0 也要数 1 拍：(0+1)×4/40000，狗变电击器 |
| 4 | 1000 | 100.1 ms | 演示二用的档位 |
| 4 | 4000 | 400.1 ms | 实际范围 267~533ms（LSI ±漂移） |
| 32 | 4000 | 3200.8 ms | 慢任务系统合适 |
| 256 | 4095 | 26214 ms | 256×4096/40000≈26.2s，接近最大窗口 |

设计口诀：**窗口下界（标称×0.667）必须大于最坏正常喂狗间隔；窗口上界（标称×1.33）必须小于你能接受的故障停摆时间**。两头一夹，档位自己就出来了。

师傅答疑：

> 问：我 ISR 已经够短了，为什么 TIM 最坏延迟还是 40µs？
> 答：40µs 不在你的 ISR 里，在主循环那个 40µs 临界区（PRIMASK 全屏蔽）里。中断打不醒关着门的人——最坏延迟=临界区剩余+上级尾巴+入栈。治法是**缩短临界区**或把该数据挪进无锁单缓冲区，不是调优先级。

> 问：演示三修好之后喂狗才 9 次，是不是喂太少了？
> 答：100ms 窗口内喂 9 次≈每 11ms 一次，频率本身没问题；重点是每次喂都发生在"延迟队列确实跑完一轮"之后——**有条件**。频率高不等于有效，无条件喂 1 万次也是零。

### 5.5 时钟树：整个系统的总水管

STM32F103 的时钟就一条主线：**源（HSE/HSI）→ [PLL 增压] → SYSCLK → AHB(HCLK) → APB1/APB2 → 各外设**。clock_tree.html 把这条线画活了，超限的段落当场变红。

必背的四段上限和一段特殊要求：

| 段落 | 上限 | 超了会怎样 |
|---|---|---|
| PLL 输出 | ≤ 72MHz | 超频：Flash 跟不上，跑飞/HardFault |
| HCLK（AHB） | ≤ 72MHz | 同上，CPU/DMA/SRAM 全在超频 |
| PCLK1（APB1） | ≤ **36MHz** | USART2-5/I2C/CAN/TIM2-7 时序错乱 |
| PCLK2（APB2） | ≤ 72MHz | USART1/SPI1/ADC/GPIO 超频 |
| ADCCLK | ≤ **14MHz** | 采样保持不够，读数"稳但全是错的" |
| USB | **恰好 48MHz** | 不是 48 就枚举失败，没有商量 |

教科书 72MHz 的完整配法（对着时钟树页 preset 一验证）：

```text
HSE 8MHz → PLL ×9 → SYSCLK 72MHz
AHB  ÷1 → HCLK  72MHz
APB1 ÷2 → PCLK1 36MHz   ← TIM2-7 时钟再 ×2 = 72MHz（硬件自动补偿）
APB2 ÷1 → PCLK2 72MHz
ADC  ÷6 → ADCCLK 12MHz ≤ 14 ✓
USB  → 72MHz ÷1.5 = 48MHz ✓  ← F103 的标准解，CPU 和 USB 两不误
```

三个高频事故，时钟树页面都有预设场景：

1. **APB1 忘 ÷2**：PCLK1=72MHz 超上限一倍。现象最有欺骗性——芯片活着、灯也闪，就是串口 2 偶发乱码、I2C 高温 NACK。因为数字电路超频初期不一定立刻死，处于"临界带"——十次里九次半是对的，就那半次要命。
2. **HSE 不起振**：CSS（时钟安全系统）把 SYSCLK 打回 HSI 8MHz。如果固件按 72MHz 配了 BRR 和 SysTick，现在所有时间基准慢 9 倍：波特率慢 9 倍=乱码，1ms 延时变 9ms。而最烂的固件连 CSS 都等不到——`while(!(CR&HSERDY));` 死循环，上电无反应。
3. **USB 要 48MHz 而 CPU 要 72MHz**：USB 预分频有 ÷1 和 ÷1.5 两档，所以 72MHz 的 PLL 输出经 ÷1.5 正好得到 48MHz。8MHz HSE ×9 = 72MHz 是 F103 的标准配置，CPU 和 USB 可以同时满足。真正无解的是 PLL 输出既不是 48 也不是 72（例如为了别的外设选 56MHz）时；这时必须在**原理图/选型阶段**改 PLL 或换芯片，固件层面无法补救。

### 5.6 调试接口：SWD 连不上的三板斧

"连不上"三个字背后是三种完全不同的病，动作顺序不能乱：

**第一板斧：电。** 万用表量 VDD/VDDA 是否在 2.0~3.6V，NRST 是否为高（约 VDD）。NRST 被外部 RC 拉低、LDO 没输出、VDDA 忘了接——任何一条都让芯片处于"没醒"状态。此时 SWD 探针报的"目标无响应"是实话，别去查线。

**第二板斧：复位与启动。** 给一次干净的上电/复位，探针要在复位释放后的窗口内 attach。有的板子固件一上电就把 PA13(SWdio)/PA14(Swclk) 配成 GPIO——复位后前几十毫秒你是能连上的，手慢就没。对策：复位按住→点连接→瞬间松手；或者 BOOT0 拉高从 System Memory 启动（那里的引导代码不会动你的 SWD 脚），擦掉固件再正常复位。这就是第 12 条坑说的"变砖救法"，**BOOT0 测试点是你在板子上给自己留的后悔药**。

**第三板斧：物理链路。** 线序（SWDIO/SWCLK/GND/3V3）、排针虚焊、线太长（>15cm 在 8MHz SWD 时钟下就开始出事）、探针和目标地不共地。示波器夹 SWCLK：连接瞬间该有一串时钟突发，什么都没有就是链路断，有时钟但无应答就是第一、二板斧的事。

师傅加一条纪律：**量产固件第一件事是确认 Readout Protection 等级**。RDP level 1 会挡住 Flash 读出（调试器通常还连得上，但读不了代码，解除保护会触发全片擦除）；RDP level 2 才是永久关死 SWD/JTAG 且不可逆。你自己调试阶段没感觉，返修台上同事连不上才发现，那时已经焊了五百台。要么留 level 0 到量产前再评估，要么在切 level 2 之前把产测方案和救砖路径跑通一百遍。

## 六、学习建议与常见坑

### 学习建议

1. **顺序不要乱**：01 → 沙盒 → 02 → 波形动画 → 03 → 04 → 时钟树。每跑完一个 .c，回到本文件对应小节对答案。
2. **改参数再跑一遍**才叫学会。每个 .c 顶部都有"动手改改"提示，改完先猜输出再验证。
3. **HTML 沙盒不是动画片**，是实验台：每个演示先在心里预测结果，再点按钮。预测错了的地方就是你真正的知识漏洞。
4. 有条件的话，把 01 的逻辑在真 Nucleo/蓝色药丸板上做一遍同样的 LED 图案，体感完全不同。

### 寄存器快照法：本关四个程序共用的心法

没有硬件怎么练寄存器？方法是把芯片"拍扁"成打印出来的快照，四步循环：

```text
① 配置   —— 写 MODER/BRR/优先级表……像真固件一样只写位域
② 快照   —— 把相关寄存器逐位打印成 01 串 + 十六进制
③ 对答案 —— 先在手心算出该是多少，再和打印对；错了就逐位找
④ 扰动   —— 改一个参数（优先级、上拉、误差），先猜快照再验证
```

对不上答案的那一刻，才是学习真正发生的那一刻。你在沙盒 HTML 里看到的位图，就是第②步的可视化版本——**每一位都要能说出它是谁、为什么是这个值**，说不出就回去查手册该位定义。这个习惯带到真板子上，就是"读回寄存器确认配置生效"的基本功：HAL 配完不读回的代码，出了问题你连案发现场都没有。

### 常见坑（每一条都有人中过，包括我）

1. **ODR 用 `=` 或 `|=` 改一个脚，抹了别人的脚**。中断一多必现，查半年。改输出只准用 BSRR（见 5.1）。
2. **EXTI 中断出来忘了清挂起位（EXTI_PR）**。挂起位是硬件置位的"电铃"，你不敲掉它，退出中断立刻再进——中断风暴，主循环饿死，现象和看门狗复位连在一起，特别迷惑。
3. **ISR 里放 `printf`（还是浮点格式）**。浮点 printf 几 KB 栈 + 毫秒级耗时，1kHz 中断里放一次，系统当场抖给你看。ISR 里最多置标志 + 搬字节。
4. **HSE 起振死等**：`while(!(RCC->CR & HSERDY));`。晶振虚焊/负载电容错 → 永远等不到 → "上电没反应"。必须带超时退 HSI（时钟树页面有交互演示）。
5. **APB1 忘了 ÷2**。HCLK 72MHz 直接灌进 36MHz 上限的 APB1，USART2 波特率悄悄翻倍、I2C 时序错乱。时钟树页面 preset"APB1 配错超限"就是它。
6. **I2C 上拉靠"经验值 4.7k"打天下**。3.3V 短总线能用；5V、长线、多器件总线，4.7k 的上升时间直接超 spec，高温下偶发 NACK 查不到原因。算！Rmin/Rmax 两个公式在 5.3。
7. **I2C 从机复位后总线死锁，驱动里没有 9 脉冲恢复**。量产现场重启大法治标不治本，固件里加总线恢复序列才治本（03 演示）。
8. **SPI 模式（CPOL/CPHA）主从不匹配**。症状是 MISO 永远读出 0x00 或 0xFF，很多人第一反应是线错了。先用示波器量 CLK 空闲电平和高低时长比例，30 秒定位模式问题。
9. **ADC 采样时间没配够就接高阻源**。10kΩ 信号源 + 1.5 周期采样时间，采样保持电容充不满，读数永远偏低且随温度漂。高阻源 → 加长采样时间或前面加一级运放跟随。
10. **看门狗无条件喂**（主循环开头一句 `IWDG->KR=0xAAAA` 完事）。主循环卡死前狗照喂不误，等于装了个从不响的火警。按心跳喂（5.4）。
11. **Sleep 模式没配唤醒源**。WFI 进去，NVIC 里一个使能中断都没有，叫不醒——"睡死"。进低功耗前检查至少一个唤醒 NVIC 中断使能且优先级合法。
12. **SWD 引脚（PA13/PA14）被固件复用成 GPIO/JTAG 其他功能，芯片"变砖"**。救法：BOOT0 拉高进 System Memory，用串口/USB 复位启动擦掉固件，再正常烧录。板子上 BOOT0 一定要留测试点或跳线，这是你给自己留的后门。
13. **GPIO 高速档直推 LED 当"炫技"**。边沿陡、振铃大、辐射强，LED 亮度一毫安没多。低速档 + 正确限流电阻才是正解。

## 七、家庭作业

1. **BRR 手算**：PCLK=42MHz，目标 500000bps 8N1。手算 USARTDIV、BRR、实际波特率、偏差百分比。这个偏差能不能接受？如果要 921600 呢？（对照 02 的程序验证手算）
2. **上拉电阻实算**：5V 系统、Iol=3mA、总线容性 250pF、要求 tr≤300ns。算 Rmin 和 Rmax。区间存在吗？不存在的话给两个工程出路。
3. **中断延迟手算**：把 04 演示一的 UART RX 优先级改成抢占级最高（raw 改 0b0000），TIM 的 1kHz 和临界区还在。预测 TIM 的新最坏延迟，改代码验证，解释为什么变了/没变。
4. **饿死复现**：04 演示二中把 TIM work 从 5000µs 改成 900µs（仍小于 1ms 周期）。预测：还复位吗？平均延迟会怎样？改完验证，并用"占用总时间/周期"这个比值解释你的结论。
5. **时钟树纸面推演**：手上有 12MHz 晶振，要 72MHz CPU + 48MHz USB + ADC≤14MHz。写出你选的 PLLMUL 和所有预分频值；如果凑不出来，说明哪个约束先让步。

### 作业要点（先自己做，再对）

1. 42e6/(16×500000)=5.25 → mant=5、frac=round(0.25×16)=4 → BRR=0x54，USARTDIV'=5.25，误差 0.00%，舒服。921600：USARTDIV=2.848，frac=round(0.848×16)=round(13.57)=14 → 2.875 → 实际 913 043bps，偏差 −0.93%，在预算内但吃满了 BRR 份额——晶振再烂一点就出局。
2. Rmin=5/3mA=1.67kΩ；Rmax=300ns/(0.847×250pF)=1.42kΩ。**Rmax < Rmin，区间为空**。出路：降容性（缩短走线、减少器件、100pF 时 Rmax=3.54k 就有了）或降速率到 100kHz（tr≤1000ns → Rmax=4.7k）。
3. UART 改成 raw=0b0000 后抢占级也是 0，而 TIM 的 raw=0b0010 高两位本来就是 00——两者**同级**，UART 不能打断 TIM，只能同拍/排队时靠子优先级抢先。因此 TIM 的最坏延迟仍由 40µs 临界区决定，**数值不变**；变的是 TIM 不能再抢占 UART，UART 的响应分布会变。想明白"同级不能抢、PRIMASK 谁都不能抢"，这题就过了。
4. 900µs < 1000µs 周期：ISR 占用比 90%，不饿死、不复位，但 TIM 平均延迟显著上升、主循环只剩 10% 的 CPU。占用比 ≥ 1 是饿死的判据，90% 是"没饿死但已经瘫"。
5. 12MHz ×6 = 72MHz CPU ✓；USB 取 PLL ÷1.5 = 48MHz ✓。——72MHz 的 PLL 输出经 ÷1.5 正好喂 USB，三者（CPU/USB/ADC）都能满足。只有 PLL 输出既不是 48 也不是 72 时，USB 才真的无解；这时要在选型阶段改 PLL 或换芯片。
