## 一、模块简介：师傅为什么先让你拿 74HC00 搭一个振荡器

你上一关在炼气期跟运放、三极管磨了两个月，练的是"连续的世界"——
电压可以是 2.73V，可以是 2.731V，也可以是 2.7315V。

这一关开始，师傅要把那个世界**关掉**。

数字电路的入门仪式不是背真值表，是：**给你一片 74HC00（四个二输入与非门），
你把其中三个反相器接成一个圈，输出接示波器。**

三个反相器首尾相接，输出必然振荡。周期是 `2 × N × tpd`，
74HC00 单门典型延迟 8ns，三个就是 `2 × 3 × 8 = 48 ns`，也就是 **20.83 MHz**。
你把第四个门也接成反相器串进去，变成 5 级，`80 ns`，**12.50 MHz**。
再加两级，7 级 **8.93 MHz**，9 级 **6.94 MHz**。

然后师傅会让你干一件"没用"的事：**接成 4 个（偶数）**。
你会发现示波上一条直线，什么都不动。
你百思不得其解，师傅就笑："偶数个反相器接成一圈不叫振荡，叫双稳态。
两个稳定点，谁能记住 1 位——**SR 锁存器就是这么来的。**"

这一课是整个数字电路的分水岭：

- **奇数级闭环 = 组合逻辑 = 振荡 = 没有记忆**
- **偶数级闭环 = 双稳态 = 锁存 = 有记忆**

同一根线，奇偶两个世界。你要是在实验室真的把这五个片子插出来量过，
下面 4 个源文件你就不会当成"理论课"来读。

真实板子上这个振荡频率还会被负载电容拖低 20%~50%。
扇出越多越慢——这就是"驱动能力"这三个字最直观的物理形态，
不用背，看示波器就懂了。

## 二、为什么"数字电路不等于 0 和 1 不用算"

很多人（包括不少做了两年硬件的）觉得数字电路简单：
"又不模拟，只有 0 和 1，能有什么？"

错得离谱。数字电路只是**把连续的复杂度藏进了标准里**，
藏起来不等于消失。你迟早要在下面这几个地方连本带利地还：

### 2.1 0 和 1 是"电压区间"，不是"电压值"

CMOS 输入到底认多少伏是 1？ datasheet 上写的是四个数：

| 参数 | 含义 | 谁定的 |
|------|------|--------|
| `VIH(min)` | 高于这个电压**保证**读作 1 | 收端说了算 |
| `VIL(max)` | 低于这个电压**保证**读作 0 | 收端说了算 |
| `VOH(min)` | 拉电流到最大时，输出 1 至少有这么高 | 发端说了算 |
| `VOL(max)` | 灌电流到最大时，输出 0 至多这么高 | 发端说了算 |

**噪声容限** = `VOH − VIH`（高电平侧）和 `VIL − VOL`（低电平侧）。

3.3V HC 系列（Vcc=3.3，负载在规范内）大致是：
`VOH ≥ 2.84V`、`VOL ≤ 0.44V`、`VIH ≥ 2.1V`、`VIL ≤ 0.8V`
→ 高侧噪声容限约 **0.74V**，低侧约 **0.36V**。

看清楚：**低侧容限只有高侧的一半**。
所以板子上ground bounce（地弹）最先打穿的永远是 0→1 误判。

再看那个"中间地带"：`VIL(max) = 0.8V` 到 `VIH(min) = 2.1V` 之间，
datasheet 明说 **不保证**。你的信号要是慢悠悠爬过这个区间
（比如经过一个大 RC，或者被长走线 + 大负载电容拖慢了边沿），
收端就会在这个区间里**反复翻转几次**——
一次跳变变成一串振荡，功耗暴涨，还可能被后一级当成多个边沿。
这就是"74HC14 施密特触发器"存在的唯一理由：它带回差，
把慢边沿重新切成快边沿，中间地带一次性穿过去。

### 2.2 混接电压：3.3V 驱动 5V，为什么有时候能跑、有时候烧

**5V 输出接 3.3V 输入的 MCU**：这是烧的那一类。
很多 3.3V 的 MCU，datasheet 上 Absolute Maximum 写的是 `VDD + 0.3V`，
也就是 **3.6V**。你直接怼 5V 进去，
输入保护二极管正向导通，电流从 MCU 的引脚倒灌进它的 3.3V 电源轨，
把整条 3.3V 轨往上顶——**轻则复位、重则闩锁（latch-up）烧毁**。
"板子跑着跑着复位"，十有八九就是这个。

反过来的方向通常能跑但要算：**3.3V 输出接 5V 输入**。
5V 的 HC 系列（Vcc=5V）判 1 的门限是 `VIH = 3.5V`，
而 3.3V HC 输出 `VOH ≥ 2.84V` —— **差 0.66V，不够**。
注意这是 **HCT** 系列（`VIH = 2.0V`）专门为"接 TTL/低压电平"设计的，
所以工程上的老话是"5V 那边用 HCT，不用 HC"。
现在更常见的解法是：电平转换 IC（TXB0108 / LSF0102 / 74LVC245）、
或者 open-drain + 上拉到 5V（**前提是收端阈值允许、且总线速率不高**）。

**5V 继电器模块 + 3.3V MCU**（本关学习目标里的例子）：
继电器模块输入通常是光耦 LED 串联限流电阻，
它需要的不是"电平"而是"电流"。所以：

- 如果模块是"低电平触发"，光耦 LED 阳极接模块的 Vcc(5V)、阴极走信号线，
  3.3V MCU **灌电流**（sink）即可——但要确认 MCU 引脚灌电流够（一般 6~8mA 安全）
  且引脚是 5V-tolerant（多数是，但一定要查表，不是"感觉是"）。
- 如果是"高电平触发"，用 N-MOS（2N7002）做开漏，漏极拉模块输入到地，
  源极接地，栅极串 1kΩ 接 MCU。**不要用三极管共射去凑**，
  除非你算过基极电阻和饱和深度。

### 2.3 open-drain 为什么必须上拉

推挽输出有两个管子轮流工作：上管导通送电流、下管导通吸电流。
开漏（open-drain）只有下面那个管子，**它只能把线拉低，没有任何能力把线拉高**。
所以：

- 不接上拉，你量那根线是**悬空的**——它在 0 和 1 之间随机漂，
  你手一碰它就变，EMC 一打它就误触发。
- 上拉电阻取值是一个**双向妥协**：
  - 太小 → 下管导通时电流 = `(Vcc − VOL) / R`。I²C 用 1kΩ @3.3V 就是 2.9mA，
    单颗没问题；但如果把强上拉接到 74HC00 这种推挽输出上，
    它输出低时，上拉电流会全部灌进下管：100Ω @3.3V 就是 33mA，
    超过 20mA 绝对最大额定，片子发烫、寿命缩短。
    **这就是"上拉选 100Ω 把驱动门灌爆"的物理过程。**
  - 太大 → 上升沿变成 RC 指数曲线。I²C 规范的 tr 是从 0.3·Vdd 量到 0.7·Vdd，
    `tr = ln(7/3) × R × Cbus ≈ 0.847 × R × Cbus`
    （电路基础关 555 公式里的 0.693 是充到一半的时间，同一个 RC 充电、不同测量口径）。
    I²C 总线电容典型 100~150pF，上拉选 10kΩ 时 `tr ≈ 0.847 × 10k × 150p ≈ 1.27 µs`，
    连 100kHz 模式允许的 1000ns 都超，而 400kHz 模式只允许 300ns——**上拉太大 = 上不去高速**。
- 取值口诀：
  **低侧**（决定功耗和驱动能力）`R_min = (Vcc − VOL(max)) / IOL(max)`；
  **高侧**（决定上升时间）`R_max ≈ tr(max) / (0.847 × Cbus)`，
  粗算记成 `R_max ≈ 1000ns / Cbus`（100kHz）即可，偏保守不吃亏。
  3.3V / 150pF 的典型答案就是 **2.2kΩ ~ 4.7kΩ**（默认选 4.7k，跑不动再往下调）。

### 2.4 74 系列输入为什么绝对不能悬空

**TTL**（74LS 等）输入悬空 ≈ 内部拉到高，读作 1，
但它是**高阻**的，一根手指、一段走线就是天线，容易误翻，还容易振荡。

**CMOS**（74HC / 74AC / 所有 MCU）输入悬空是**真的会出事**：

1. **误导通**：CMOS 输入阻抗 10¹²Ω 级，静电、感应、PCB 漏电
   都会把它拖到 1.5V 附近——也就是上面那个"不保证"的中间区。
   此时**上管和下管同时半导通**，Vcc 到 GND 直通，
   芯片内部短路电流，功耗从 µW 级暴涨到几十 mW 甚至更多。
2. **发热**：一个片子没事，十个片子悬空输入一起半导通，
   板子摸上去温的，静态电流从 200µA 变成 20mA——你查三个月都查不出来。
3. **不确定**：同一块板，冷启动一个值、热启动另一个值，
   机壳盖上和拿掉都不一样。

所以：**每一个没用到的输入，都必须接地或接电源（通过电阻）**，
不允许留空脚。上拉/下拉电阻取 10kΩ 是通解：
既能可靠拉定电平，又不会在外部强驱动时灌入过大电流。

## 三、学习目标（逐条可检验）

学完这一关，你应该能做到下面 7 件事，**每件都能当场验收**：

1. **能算噪声容限**：给任意两片 datasheet（发端 VOH/VOL + 收端 VIH/VIL），
   能立刻算出高低两侧噪声容限，并说出哪一侧先出问题、为什么。
2. **会给 3.3V MCU 驱动 5V 继电器模块选方案**：
   能列出 3 种（开漏+上拉 / 电平转换 IC / MOS 管驱动），
   指出各自的电流方向、速率上限、成本，并**把上拉电阻上下限算出来**
   （不是"随便挑个 10k"）。
3. **能用卡诺图/QM 化简 4 变量函数**：
   给定最小项和无关项，30 分钟内手推出最简与或式，
   并说出"化简省了什么"——**省片子、省功耗、省门延迟级数**，
   并且能画出两级与非（NAND-NAND）形式。
4. **能解释毛刺从哪来、什么时候有害**：
   给一个 4 位二进制计数器 + 74HC21 译码"0110"的场景，
   能说清为什么会产生一根约 13ns 的尖峰，
   以及三种解法（同步+并行进位 / 输出打一拍再译码 / 加选通时钟）。
5. **能算 fmax 和保持裕量**：
   给 Tco / Tpd / Tsu / Th / skew / jitter，
   能算出 `fmax = 1/(Tco+Tpd+Tsu−skew−jitter)` 和保持裕量，
   并**说出为什么降频能救建立违例但绝对救不了保持违例**。
6. **能算 MTBF 并解释同步器**：
   给 t_settle / τ / f_clk / f_data，
   能算 MTBF，能讲清两级同步器为什么是底线、
   为什么两个 FF 必须挨着放且不能被综合器优化掉。
7. **能写一个健壮的表驱动状态机**：
   有 default 分支、有安全态、有越界自检、
   知道"连发规则必须清计数器"这类计时器清零陷阱；
   并且能解释硬件里"case 没有 default"为什么等于送锁存器。

### `01_logic_gates.c` —— 4 变量卡诺图 / Quine-McCluskey 化简器

**用途**：输入"最小项 + 无关项"，输出最简与或式（SOP）、代价对照、
两级与非形式，并且逐条枚举 16 项真值表验证等价性。

**为什么不是"背卡诺图"**：卡诺图是**图形化的 Q-M**，
两者结果一致，但卡诺图靠人眼找圈、四变量以上就抓瞎，
Q-M 是算法，能证明"找到的确实是质蕴含项"。
这个文件把 Q-M 实现出来，你顺便能看到"化简"这件事的机器版本长什么样。

**怎么编译运行**：
```
chcp 65001
gcc -std=c17 -O2 -Wall -Wextra 01_logic_gates.c -o 01_logic_gates.exe
.\01_logic_gates.exe
```

**预期看到什么（关键数字，跑出来跟这个对账）**：

- 例 1 **三人投票多数器** `m = {6,7,10,11,12,13,14,15}`：
  最简式 = **`F = AB+AC+BC`**（这就是本关的自查答案，化简器要是没算出这三项就是你环境有问题）。
  代价：未化简 **与门 24 / 或门 7 / 反相 4 / 总 35 门 / 输入脚 66 / 延迟 7 级**；
  化简后 **与门 3 / 或门 2 / 反相 0 / 总 5 门 / 输入脚 10 / 延迟 3 级**。
  两级与非折算 **5 个二输入与非门 → 74HC00 需要 2 片**。
- 例 2 **BCD 七段译码 g 段** `m = {2,3,4,5,6,8,9}`、`X = {10..15}`：
  最简式 = **`g = A+B'C+BC'+CD'`**，9 门 / 输入脚 15 / 延迟 4 级。
  对照"不敢用无关项"：`A'B'C+A'BC'+AB'C'+A'CD'`，**15 门 / 输入脚 26 / 延迟 5 级**。
  **无关项值不值钱，看这两行就完了。**
- 例 3 **4 位奇校验**：化简前后一模一样，35 门 7 级——
  1 在卡诺图上是棋盘格，谁也挨不着谁。**这类函数天生该用异或门（74HC86）**。
- 环形振荡器：N = 3 / 5 / 7 / 9 → **20.83 / 12.50 / 8.93 / 6.94 MHz**（tpd = 8ns）。
- NAND-NAND 等价性验证：**16/16 PASS**（两个用例各 16 项）。

**学习重点**：
① 合并的物理本质是"相邻最小项消去一个变量"；
② 代价模型不是数门个数，要数**门输入脚总数**和**延迟级数**——
   这两个才分别对应"用几片片子/多少功耗"和"多慢"；
③ 无关项是白捡的便宜，圈能画大就画大。

### `02_sequential_lab.c` —— 时序逻辑周期精确仿真台

**用途**：带每门传播延迟参数的边沿触发 D 触发器模型，
逐个时钟沿打印**每个输出在时钟沿之后多少 ns 才翻**，
把"延迟累积"和"译码毛刺窗口"直接打印成数字。

器件模型（74HC 系列 5V / 25℃ 典型）：`D 触发器 CLK→Q = 13 ns`、`门 = 8 ns`。

**怎么编译运行**：
```
chcp 65001
gcc -std=c17 -O2 -Wall -Wextra 02_sequential_lab.c -o 02_sequential_lab.exe
.\02_sequential_lab.exe
```

**预期看到什么（关键数字）**：

- **实验 1 异步（纹波）4 位计数器**，`0111 → 1000` 这一拍：
  跳变时刻 `+13 / +26 / +39 / +52 ns`（每过一位多付一个 13ns）。
  译码器在这一路上依次"看到" **0110 → 0100 → 0000 → 1000**，
  目标是 8，但中间冒出 **3 个假状态**：`6`（t=13.0ns）、`4`（t=26.0ns）、`0`（t=39.0ns），
  每个持续 **13.0 ns**。
  → 若用 74HC21 译码"0110"，你会得到一根**宽约 13 ns 的正尖峰**，
    足够让下一级 MCU 的外部中断白触发一次。**这就是毛刺，不是玄学。**
- **实验 2a 同步 + 串行使能（进位一级级传）**：假状态还是 3 个，
  但每个只持续 **8.0 ns**（跳变时刻 +21/+29/+37/+45）。
  （74HC393 本身是异步纹波计数器，对应实验 1，不是同步计数器。）
- **实验 2b 同步 + 并行进位（74HC161/163 风格）**：所有位同时 `+13`，**假状态 0 个**。
- **实验 3 位宽怎么吃掉 fmax**：
  纹波 2/4/8/16 位 → 最长链 26/52/104/208 ns → fmax **38.46 / 19.23 / 9.62 / 4.81 MHz**；
  同步并行恒为 13ns → **76.92 MHz**（与位宽无关）。
  **每加一位，纹波的最高频率对折一次。**
- **实验 4 移位寄存器**：所有位共享同一 CLK → 同时翻，**没有累积延迟**，
  这就是 74HC595 的全部原理。
- **实验 5 异步清空的竞争**：清零瞬间停在 1001(9)，
  Q0 在 **13.0 ns** 落地、Q3 在 **37.0 ns** 落地（走线多穿 3 级缓冲），
  这 **24.0 ns** 窗口里读数是 **8**——一个谁都没设计过的值。
- **实验 6 锁存器 vs 触发器**：CLK 高电平期间 D 上有一次 10ns 宽的 0→1→0 抖动，
  t=20ns 时**锁存器 Q = 1**（原样搬过去了），**触发器 Q = 0**（只认上升沿那一瞬）。

**学习重点**：
① 纹波 = 级数 × tpd，而且**只在特定状态序列才最坏**（0111→1000 才是），
   测不出来不代表不存在；
② 毛刺不是"坏了"，是"各位不同时到位"的必然结果；
③ **能用触发器就别用锁存器**——锁存器是透明的，
   而且用锁存器你还得多一级时钟反相，时序分析复杂度直接翻倍。

.\03_setup_hold.exe
```

**预期看到什么（关键数字）**：

- **实验 1**，基线 `Tco=6.0  Tpd=4.0  Tpd(min)=3.2  Tsu=2.0  Th=1.0  skew=0.5  jitter=0.3`：
  - **场景 A（正常布线）**：fmax = 1/11.20ns = **89.29 MHz**。
    20MHz 建立裕量 **+38.80**、80MHz **+1.30**、85MHz **+0.56**、
    90MHz **−0.09** 起判"建立失败（降频可救）"；保持裕量恒为 **+7.70**（跟周期无关）。
  - **场景 B（走线加长，Tpd 4→8ns、Tpd(min) 3.2→6.5ns）**：fmax = 1/15.20 = **65.79 MHz**，
    100MHz 处建立裕量 **−5.20ns**；保持裕量 **+11.00**（延迟下限也变大，反而更不容易保持违例）。
  - **场景 C（skew 拉到 6.5ns + 短走线）**：**fmax 表面算出来 1/5.20 = 192.31 MHz**，
    但保持裕量恒为 **−0.50 ns**，9 行全部判"保持失败（降频无用）"。
    程序会额外打一行：`保持裕量 -0.50 ns < 0，与 Tclk 无关，上面 9 行全是废的`。
    **这是本文件最该记住的一张表：只看建立时间的 STA 报告会给你一张全绿的假绿灯。**
- **实验 2 MTBF**（`MTBF = exp(t_settle/τ) / (f_clk × f_data)`）：
  `f_clk = f_data = 100MHz、Tsu = 2.0ns`：

  | τ (ns) | 同步级数 | t_settle | 多久错一次 |
  |--------|----------|----------|------------|
  | 0.5 | 1 | 8.0 | **不足 1 ns**（等于每个时钟沿都在赌） |
  | 0.5 | 2 | 18.0 | **431.123 ms** |
  | 0.5 | 3 | 28.0 | **6.63 年** |
  | 1.0 | 1 | 8.0 | 不足 1 ns |
  | 1.0 | 2 | 18.0 | **6.566 ns** |
  | 1.0 | 3 | 28.0 | **144.626 µs** |

  `f_clk = f_data = 10MHz`（t_settle = 98/198/298ns）：**六行全部"天文数字（> 3000 万年）"**。
  收益不是"频率降了 10 倍"带来的，是 **t_settle 从 8ns 变成 98ns，指数项吃了全部红利**。
- **实验 3 格雷码 + 异步 FIFO**：0~15 往返还原 **PASS**；
  深度 8、指针 4 位（多留 1 位回绕位），**46 次操作，空满误判 0 次：PASS**，
  收尾 `wptr=11 rptr=3`，此时 FIFO 满（空标志 0、满标志 1 全对）。
- **实验 4 固定种子蒙特卡洛**（`srand(20260315)`、N = 1,000,000、
  `Tclk=10.0 Tsu=2.0 Th=1.0 τ=2.5`）：
  亚稳态事件 **299539 / 1000000**（窗口占周期 30.0%）：

  | 同步级数 | 可用稳定时间 | 错误次数 | 错误率 | 多久错一次 |
  |----------|--------------|----------|--------|------------|
  | 0 | 0.0 ns | 299539 | 29.95390% | **33.385 ns** |
  | 1 | 8.0 ns | 12001 | 1.20010% | **833.264 ns** |
  | 2 | 18.0 ns | 209 | 0.02090% | **47.847 µs** |
  | 3 | 28.0 ns | **0** | 0.00000% | 本 100 万次内未出现 |

  换机器、换编译器，只要种子是 `20260315`，这四个数一个都不会变——
  **这就是做实验必须固定种子的原因：不然你对不上账，也骗不了自己。**

**学习重点**：
① 建立裕量里有 Tclk，保持裕量里**没有** Tclk —— 这一句解释了一切；
② skew 对建立是帮忙（`−skew`），对保持是拆台（`−skew`），**同一把刀两头砍**；
③ 同步器只能降低概率，永远不能归零；
④ 跨时钟域的每一位都要过同步器，**两个 FF 必须物理相邻且不能被优化/retiming 挪走**；
⑤ 多位指针跨域必须转格雷码，或者干脆用异步 FIFO。

### `04_fsm_traffic.c` —— 表驱动状态机引擎 + 交通灯 + 按键消抖

**用途**：一个通用 FSM 引擎（状态枚举 + 事件枚举 + 一张 `const Rule table[]` + default），
套两个真实场景：十字路口交通灯（含故障安全态）和按键消抖。
外加一个**对照组**：把 default 分支删掉，同一段激励重跑一遍。

**怎么编译运行**：
```
chcp 65001
gcc -std=c17 -O2 -Wall -Wextra 04_fsm_traffic.c -o 04_fsm_traffic.exe
.\04_fsm_traffic.exe
```

**预期看到什么（关键数字）**：

- 交通灯转移表 **23 条规则**（其中 FAULT 显式占 6 条——每个工作状态一条 + SAFE 一条）。
  计时档位：红 4 拍 / 红黄 1 拍 / 绿 6 拍 / 黄 2 拍 / 行人 3 拍。
- 40 拍轨迹：0~3 拍红灯计时，**第 4 拍进红+黄，第 6 拍放绿灯**；
  第 9 拍行人按钮**只记录标志，绝不打断绿灯**；
  第 12 拍车流传感 → 绿灯提前收尾进黄灯；
  黄灯计满 2 拍，因为标志 = 1，**第 15 拍进行人态，第 19 拍回红灯**；
  第 28 拍 FAULT → 显式规则进 SAFE；第 32 拍 CLEAR 才回红灯；
  第 36 拍注入**未定义事件 99**（表里根本没有这个编码）→ **default 兜住，照样进 SAFE**，
  第 38 拍 CLEAR 又出得来。
  **汇总：default 命中 1 次，非法状态 0 次 → PASS（状态永远合法）。**
- **对照组（删掉 default）**：第 3 拍喂进 99，状态立刻变成枚举里根本不存在的值；
  第 4~6 拍喂的是完全正常的 TICK，**一条规则都匹配不上，机器永久卡死**。
  **非法状态 4 次。**
  硬件里一模一样：`case` 没有 default，综合器给你锁存器 + 未定义状态；
  上电、单粒子翻转、外部干扰把状态推进未编码的组合，就再也爬不出来。
- 消抖状态机（10ms 采样、消抖 3 次=30ms、长按 20 次=200ms、连发每 8 次=80ms）：
  第 4 个样本那个 10ms 毛刺被判为抖动**直接作废**（0 次误报按下）；
  第一次真按下要等到**第 9 个样本**才报「按下」，第 13 个样本松手报「短按（单击）」；
  第二次从第 20 拍按住不放，**第 43 拍报「长按有效」，第 51 拍报第一次连发**。
  **汇总：毛刺作废 1 次、确认按下 2 次、短按 1 次、长按 1 次、连发 1 次。**

**学习重点**：
① 状态逻辑是**数据**（表），不是 if-else 面条——评审时一眼看完全部组合；
② 故障路径要写成"看得见的行"，**每个状态单独一条 FAULT 规则**，
   写成 if-else 你根本不确定是不是每个分支都处理了故障；
③ default 必须存在，且必须指向**安全态**，不是指向"什么都不做"；
④ **计时器什么时候清零**比状态本身更容易写 bug（连发规则不 reset → 每拍都发）；
⑤ 消抖阈值一律写成「毫秒 / 采样周期」，别写死数字。

## 五、学习建议与常见坑

**学习建议**：

- **每个 .c 先猜输出再跑。** 打开源码，看激励数组，
  拿纸笔写"第 12 拍应该在什么状态"、"0111→1000 最坏延迟应该是多少 ns"，
  再跑。猜错了才是这一课真正的收获。
- **改参数再跑一遍。** 02 里把 `TPD_FF` 从 13 改成 3（相当于换成 74AC 系列），
  fmax 表立刻变；03 里把 skew 从 0.5 拖到 6.5，看场景 C 怎么把全绿变全红。
  **只会跑不会改，等于没跑。**
- **配合实物。** 手边有 74HC00 + 面包板 + 示波器的，
  一定把环形振荡器插出来量一次。量到 12MHz 而不是理论的 12.50MHz，
  那 4% 的差异就是你的第一份"寄生参数"实测数据。
- **公式抄在便利贴上贴屏幕边**（附录那张）。
  噪声容限、fmax、MTBF、`tr ≈ 0.847·RC`——这四条要看到能条件反射。

**真实坑（每一条都有人中过招，包括师傅本人）**：

1. **CMOS 输入悬空 → 误导通 + 功耗暴涨。**
   74HC 没用到的输入脚留空，芯片内部上下管同时半导通，
   静态电流从 200µA 变成 20mA，片子摸着是温的，
   而且电平随机——盖上机壳一个值、打开机壳另一个值。
   **解法**：所有未用输入，通过 10kΩ 明确接地或接 Vcc，一个不留。

2. **把 latch 当 flop 用。**
   74HC373（锁存器）当成 74HC74（触发器）用，
   CP 高电平那半周期里数据是**透明直通**的，
   前级的毛刺原样搬到输出，而且时序分析里多一个"透明窗口"要处理。
   FPGA 里更惨：综合器默默给你推断出 latch，
   报 warning 你没看，最后板子中概率出错。
   **解法**：一律用边沿触发；RTL 代码里 `if` 没有 `else` 导致锁存器推断，
   这种 warning 必须当 error 处理。

3. **状态机漏 default 分支 → 跑飞且爬不回来。**
   04 的对照组演示得很清楚：状态一旦进入未编码组合，
   **后面喂正常输入也一条规则都匹配不上**，永久卡死。
   上电顺序、单粒子翻转、EMI 干扰都能把你推进那种组合。
   **解法**：`default` 指向安全态 + 运行中检查状态变量是否越界 + 越界立即复位。

4. **只加 100nF 消抖，结果抖动 15ms 打穿。**
   按 RC 算，10kΩ × 100nF，τ = 1ms，"消抖绰绰有余"。
   但按键 datasheet 写的抖动时间是**典型值不是上限**，
   廉价轻触开关用久了、低温下，弹跳能到 5~10ms，甚至 15ms。
   电容这边刚放完电，触点又弹回去了——**MCU 读到第二个边沿**。
   **解法**：硬件 RC 取到 10~20ms + 施密特（74HC14）整形，
   软件再做 20~30ms 的稳定判定（04 里那个状态机），**双保险**。

5. **两级同步器被编译器 / 综合器优化掉。**
   代码里写 `sync_r1 = async_in; sync_r2 = sync_r1;`，
   看起来加了，但综合器觉得"这就是根线"，
   把两级合并、或者做 retiming 把两个 FF 拆到相距十万八千里——
   **亚稳态传播的"额外一个周期"红利直接归零**。
   **解法**：加综合约束（`ASYNC_REG=TRUE`、`syn_preserve`、`dont_touch`），
   布局上强制相邻，并且在物理约束报告里**核对这两个 FF 真的挨着**。

6. **open-drain / I²C 忘接上拉。**
   现象最迷惑：读出来全是 1，或者飘忽不定，
   有时看着能通（总线寄生电容存了点电荷），动一下排线就不通了。
   **解法**：SCL/SDA 各一个上拉（3.3V 系统默认 4.7kΩ，跑高速换 2.2kΩ）。
   模块上电先用万用表量两根线是不是高电平，**这个检查 30 秒能省你两小时**。

7. **上拉选 100Ω 把驱动门灌爆。**
   想"加快上升沿"于是上拉取到 100Ω @5V。
   低电平时电流 = `(5 − 0.44) / 100 = 45.6 mA`——
   超出 74HC 系列单脚 `IOL` 规范（±20mA 绝对最大），
   `VOL` 被抬高到 1V 以上（判 0 门限是 0.8V，**直接误判成 1**），
   片子发烫，长期可靠性报废。
   **解法**：上拉下限按 `R_min = (Vcc − VOL(max)) / IOL(max)` 算，
   想提速应该减小总线电容（缩短走线、减少挂载）而不是硬压电阻。

8. **混合电压不做电平转换，烧输入。**
   5V 传感器输出直连 3.3V MCU，
   Absolute Maximum `VDD + 0.3V = 3.6V`，5V 从引脚保护二极管倒灌进 3.3V 轨，
   把整条轨往上顶 → 板子跑着跑着复位 / latch-up 烧毁。
   **解法**：5V-tolerant 引脚要**在表上查到那一栏**才算（"看着像"不算）；
   不确定就上电平转换 IC，或者 分压 + 施密特。
   注意分压方案对**方向**有要求：只能降 5→3.3，反过来不行。

9. **复位释放时外设还没稳定就初始化。**
   上电后 MCU 复位一释放就狂发 I²C 初始化命令，
   但此时 EEPROM / 传感器 / 电源轨还在爬坡，
   I²C 外设可能正处在"半上电"状态把 SDA 拉住 —— 初始化全部 NACK，
   而且失败状态被写进标志位，之后再也不重试。
   **解法**：复位后**延时 10~50ms 再初始化**（或做带重试的等待循环），
   电源轨用 power-good 信号做硬件门控，
   初始化失败要有明确的重试与降级策略，不能"失败一次就认命"。

10. **把"仿真通过"当成"硬件没问题"。**
    仿真器里 `#13` 是干净的一个数，真实片子上 tpd 随温度、电压、负载在
    **6~15ns** 之间漂，同一片不同门也不同（datasheet 只保证 max）。
    所以：仿真算出来裕量 0.5ns 的设计，板子上一定挂；
    **裕量至少留 20%~30%**，并且要按 datasheet 的 worst case 算，
    不是按典型值算——**典型值 = 一半的片子比它慢，你没算那一半。**

11. **卡诺图化简出"最简"就上，不管毛刺。**
    最简 SOP 是**面积最优**，不是**时序最优**。
    某些相邻最小项分属不同乘积项时，输入变化的瞬间会出现"两个与门同时为 0"的空窗，
    输出打一个反毛刺。
    **解法**：关键路径上给输出打一拍寄存器（同步化），
    或者加冗余项（consensus term）覆盖切换空窗。
    01 只讲化简，**毛刺在 02 里现原形**，顺序别搞反。

## 六、家庭作业（5 道，全是要动手的）

**作业 1：把你手边任何一块板的"输入悬空"找出来。**
- 找一块有 74 系列或者 MCU 未使用 GPIO 的板子（面包板搭的也算）。
- 查出所有**没有连接**的 CMOS 输入脚（看原理图 + 万用表通断档确认）。
- **报告要求**：
  ① 列一张表：脚位、内部是什么（输入/输出/未用）、当前电位（万用表量，
     应该读到乱七八糟的中间值，比如 1.3~2.1V）；
  ② 把整个系统供电电流用电流档串进 Vcc 回路测出来（µA/mA 级），记录下来；
  ③ 用 10kΩ 电阻把这些悬空输入逐个接地，**再测一次电流**，
     报告电流下降了多少、这些脚的电位是不是稳定在 0V 附近；
  ④ 一句话结论："如果不处理，这块板在高温/潮湿环境下会发生什么。"

**作业 2：亲手做一次 3.3V ↔ 5V 接口设计，并用万用表验。**
- 场景：3.3V MCU 的 GPIO 控制一个 5V 继电器模块（或 5V LED 驱动板），
  同时需要读回一个 5V 开漏的故障信号。
- **要求算出来**（不许先接线）：
  ① 控制方向选什么方案（开漏+上拉 / MOS / 电平转换 IC），为什么；
  ② 读回方向的**上拉电阻上下限**：
     下限按"MCU 引脚 IOL 与 VOL 规范"算，
     上限按"允许的上升时间 + 估的总线电容（按 100pF 算）"算，
     给出区间并说明最终选哪个 E24 值；
  ③ 5V 信号进 3.3V MCU：查你手上 MCU 的 datasheet，
     找到写着 5V-tolerant 的那一栏并**抄出原话/引脚列表**（找不到就是找不到，
     找不到就是必须分压）。
- **实测**：接好后量高电平、低电平各是多少，
  跟噪声容限对上；量继电器吸合瞬间的电源电压跌落（万用表 DC 档也能看到抖一下）。

**作业 3：用卡诺图 + `01_logic_gates.c` 双重验证一个你自己设计的译码器。**
- 设计一个"**两位 BCD 检测器**"：输入 4 位 BCD（A 高位），
  当数值是**质数**（2,3,5,7,11 里 BCD 合法的是 2,3,5,7）时输出 1，
  输入 1010~1111 是非法 BCD，标为无关项 X。
- **要求**：
  ① 手画卡诺图，圈出最简与或式（写清每个圈覆盖了哪些最小项）；
  ② 把最小项和无关项填进 `01_logic_gates.c` 的 `ms[]` / `dc[]` 重新编译运行，
     对比程序的输出和你的手写结果**是否完全一致**；
  ③ 报告里要抄程序打印的"代价对照"两行：
     化简前后的**门总数、输入脚总数、延迟级数**各是多少；
  ④ 再做一次"不敢用无关项"（把 `dc[]` 清空）的版本，
     说明**无关项到底给你省了多少**。

**作业 4：用 `setup_hold_animator.html` + `03_setup_hold.c` 复现一次"保持违例"，并给出解法。**
- 场景设定：`Tco = 2.0ns`、走线延迟 `2.0ns`（min 也 2.0）、`Th = 1.0ns`，
  时钟树偏差 `skew = 4.0ns`（收端时钟**晚**到 4ns）。
- **要求**：
  ① 手算保持裕量，说明是不是违例、违例多少；
  ② 说明把时钟从 200MHz 降到 1MHz 能不能救——**必须引用保持裕量公式解释为什么**；
  ③ 给出 3 种真正的解法（加缓冲/绕走线抬高延迟下限、把 skew 收回来、
     改布局让两个 FF 就近），
     并说明每种解法各自的**副作用**（加缓冲会同时吃掉建立裕量，你打算怎么补）；
  ④ 用 animator 的"偏 skew 破坏保持时间" preset 验证你的计算，
     截图或抄下裕量数值；把 `03_setup_hold.c` 场景 C 的参数改成这个场景重新编译，
     报告扫描表 9 行全部是什么判定。

**作业 5：给一个真实按键写消抖，并做压力测试。**
- 用任意 MCU（或 FPGA、或就是 `04_fsm_traffic.c` 改）实现 10ms 采样的消抖状态机。
- **要求**：
  ① 用示波器（没有就用逻辑分析仪 / MCU 自己打时间戳）抓一次**快速连按**时
     原始引脚电平的边沿数，报告一次按键实际有多少个边沿；
  ② 把消抖阈值从 3 次（30ms）逐步减小到 1 次（10ms）、2 次（20ms），
     每次连按 50 下，报告"一次按键被识别成几次"的统计——
     找到你手上这个按键开始出错的阈值；
  ③ 报告里说明：如果你的采样周期从 10ms 改成 5ms，
     代码里哪些数字必须同步改（**引用 04 里 `DB_DEBOUNCE` 写成
     `毫秒 / 采样周期` 的写法**）；
  ④ 加一条"长按 + 连发"，并**明确说明计数器在哪条规则上清零**
     （这就是 04 里 `reset=1` 的那个坑）。

**交作业形式**：一页纸，五个小表 + 每道题一句"我这次错在哪 / 我哪个假设不成立"。
写"全部符合理论"的，师傅要重查——**数字电路不可能全对，全对说明你没测够。**

## 七、本关通关标准

有一条打不上勾，回去补那一条。

- [ ] **能讲电平**：不看资料，讲清 `VIH/VIL/VOH/VOL` 各是谁规定的，

## 附：本关公式与常数速查（贴墙上）

```
噪声容限（高）   NM_H = VOH(min) − VIH(min)
噪声容限（低）   NM_L = VIL(max) − VOL(max)
3.3V HC 典型     VOH≥2.84  VOL≤0.44  VIH≥2.10  VIL≤0.80  → 0.74V / 0.36V
5V  HC 判 1      VIH = 3.5V        5V HCT 判 1  VIH = 2.0V  ← 接低压就选 HCT
5V TTL 判 1      VIH = 2.0V        绝对最大     VDD + 0.3V
上拉下限         R_min = (Vcc − VOL(max)) / IOL(max)
上拉上限         R_max ≈ tr(max) / (0.847 · Cbus)     I²C 粗算：R_max ≈ 1000ns / Cbus
开漏上升时间     tr ≈ 0.847 · R · Cbus（0.3Vdd→0.7Vdd，ln(7/3)≈0.847）
扇出             N = IOL(max) / IIL(每负载)   （CMOS 静态≈0，看动态/容性）

合并原理         A'BC + ABC = BC           （相邻最小项消一个变量）
两级万能         SOP = NAND( NAND(项1), NAND(项2), … )
环形振荡器       f = 1 / (2 · N · tpd)      N 必须为奇数（偶数=双稳态=锁存）

纹波最坏延迟     t_max = N位 × tpd          每加一位 fmax 对折
建立裕量         M_su = Tclk − (Tco + Tpd + Tsu − skew − jitter)
最高频率         fmax = 1 / (Tco + Tpd + Tsu − skew − jitter)
保持裕量         M_hd = Tco + Tpd(min) − Th − skew   （★ 没有 Tclk！）
亚稳态 MTBF      MTBF = exp(t_settle / τ) / (f_clk · f_data)
亚稳态解除时间   t_res = −τ · ln(u)         u ∈ (0,1) 均匀随机
格雷码           gray = bin ^ (bin >> 1)
格雷码→二进制    for (s = g; s >>= 1;) g ^= s
异步 FIFO        空 = (wptr == rptr)
                 满 = ((wptr ^ rptr) & MASK) == (1 << (PTR_BITS−1))
                 ★ 指针必须比地址多 1 位（回绕位），否则空满分不清

按键抖动         典型 1~5 ms，实际可达 10~15 ms（datasheet 是典型值不是上限）
硬件消抖         RC 取 10~20 ms + 施密特（74HC14）
软件消抖         10 ms 采样 × 连续 3 次稳定 = 30 ms 判定
常见片子         74HC00 四2输入与非 / 74HC02 或非 / 74HC04 六反相
                 74HC74 双D触发器 / 74HC75·373 锁存器（别乱用）
                 74HC86 四异或 / 74HC14 施密特反相 / 74HC21 四输入与
                 74HC393 双4位行波计数 / 74HC161 4位同步并行计数 / 74HC595 移位
```
